# Original agent documents and human comparison

0258 connects [retained per-role verification](GENERATION-OUTPUT-HISTORY.md) to a
combined, owner-authorized `intent.development.history` HTTP/MCP query and a
read-only panel in the actual Next application. It is not a separate preview.

## What the person can inspect

For a known recorded run, **Read original agent documents** verifies its original
Brief, Spec and Test Agent Exam. The panel labels the source and latest preserved
revision, expired execution, missing documents and unresolved roles. Each document
can be compared with the selected preserved editor snapshot. Exact text equality
is reported separately from rendered Markdown; this is not a semantic diff.

The view has no adoption, generation, retry, signature or GitHub-save action.
It never replaces editor content or its save base. Selection, preserved editor
snapshot, identity, expiry, hidden-page and unload changes clear private output; stale in-flight
responses cannot repopulate another context. Failure clears the previous result
and leaves working text unchanged. An unpreserved editor is not represented as a
server-verified snapshot.

## Combined verification

1. A current human needs the distinct history tool grant and matching owner,
   organization, product and repository. Services remain explicit and uninstalled.
2. Present observation-history permission covers both planned roles, even when
   no role has completed. Separate input/source/result/records/key checks still
   apply. Old execution grants and budget configuration provide no read authority.
3. Original input and any retained assessment are restored through 0256. One
   read-only PostgreSQL snapshot includes both roles, including absent/pending work.
4. Every succeeded role uses 0257's exact recorded-SDK request/response/result
   verification. The combined reader also verifies the Architect transcript and
   the Test Agent's exact predecessor result; a lone Exam cannot establish a pair.
5. After all SDK callbacks finish, both roles are read back under fresh records,
   source/profile, key and identity checks. Only deterministic SDK verification of
   the exact same original/request/response is memoized within that one read.
   No authority lookup or content cache survives the request.
6. Final original/latest-revision and operation/step snapshots must agree with
   the initial snapshots. Mid-read completion or editing fails instead of mixing
   observations or silently chasing the writer. Current identity is checked again.

The browser receives strict parsed role output and inert result/predecessor/input
digests, never raw prompts, source packets, profiles, provider request/response
bodies, keys or continuation checkpoints. Output hashes and ordered predecessor
linkage are verified at the shared tool and browser boundaries. Status is
`pending`, `partial`, `complete`, `needs-clarification` or `attention-required`;
historical and expired labels remain independent. `complete` means both recorded
roles are available, not an accepted Exam or a current candidate-save decision.

Reads neither reserve budget nor change SQL, workflow state, retention or Git.
Server admission and browser streaming remain bounded, including after timeout,
shutdown and ignored cancellation. No new provider binding or migration is added.

## Remaining acceptance

The actual React graph and authenticated query contracts are exercised with
synthetic HTTP/SQL/SDK authority. That is not real signed-in model/provider or
saved-repository acceptance. Current records adoption (D1), model-budget approval,
live authority and semantic quality remain unresolved; the existing credential
decision is not reopened.

0259 adds [all-preserved-revision discovery](RETAINED-RUN-DISCOVERY.md) for captured
scope and drafting originals after navigation. Admissions without captured inputs
are not enumerated. Immutable final-save preparation, confirmation, authorized start
and the complete human acceptance matrix remain open. See [0258 evidence](../intent/0258/EVIDENCE.md)
and [the journey plan](INTENT-JOURNEY-PLAN.md).
