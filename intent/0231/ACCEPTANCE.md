# Acceptance boundary

Development acceptance requires a fresh production-component mount to find a
working draft, preview it without replacing new text, explicitly restore, resume
the retained run by a read-only query and adopt editable results. No new prepare or
start may occur during completed-run recovery. Discovery failure is not emptiness.
SQL checks must cover owner/configuration isolation, cursor pages, empty references,
retained latest-run metadata, concurrent changes and current-access denial.

Synthetic HTTP/source/model authority and database tests do not establish real
records-policy approval, source completeness, semantic accuracy, model quality,
human usability or a saved repository bundle. DOM accessibility checks do not
replace real-browser visual/keyboard/narrow-screen acceptance. I1–I6 remains open.
Canonical Exam and signed Architecture/records policy remain unchanged.
