# Acceptance boundary

Development acceptance requires current-human start through actual HTTP and
encrypted SQL, plus real isolated Temporal start/recovery with reference-only
history. Lost responses and concurrent requests must converge on one retained run
and one set of batch reservations. Foreign workflow inputs/policies, expiry,
changed source and revoked authority cannot produce a valid acknowledgement.

Synthetic authority, records adoption, keys, costs and model responses are fixtures,
not approvals or semantic-quality evidence. No live migration, paid model call,
runtime Git save, authentication change, gate, deployment or release is authorized.
D1 remains unsigned/inactive and the first-test model budget unapproved.

I1–I6 acceptance still requires actual editor binding, real current authority,
semantic evaluation and a demonstrated human journey ending in an authorized exact
repository save and reopen. This increment does not claim those results.
