# Intent Brief — Original save recovery

## Problem and outcome

A lost save response must not force the human to submit the same intent again.
The application needs a read-only answer about the original operation and an
exact reopen link only when the server verifies its saved Git bundle.

## Scope and limits

Connect encrypted original recovery, native Git receipt inspection, the shared
query and actual signed-in status-to-bundle interaction. Keep unknown, missing
and conflicting receipts distinct without turning them into retry permission.
Preserve current drafts, privacy, original identity and existing lifecycle clocks.
No new operation, workflow, dispatch, model spend, grant, gate, deployment, records
activation or real Git write. Save preparation/confirmation/start remain separate.
