# Acceptance boundary

Developer evidence only. The new integration uses actual PostgreSQL, encryption,
original/request/result readers and the development step runner. Model bodies,
responses, usage, identities, keys, grants and budget are synthetic fixtures. There
is no real network model transport or independent agent/human acceptance verdict.

Runner/store reconstruction uses the same test process and running database, not a
machine crash or restored backup. A request row is not proof of provider delivery;
a response row is not a gate signature. Quarantined/expired records need separately
authorized investigation/reconciliation before they can inform any new attempt.

D1 remains unsigned/inactive, the real database baseline stays at seven migrations,
and I1–I6 remain incomplete. No live model spending, migration, runtime GitHub save,
release, deployment, deletion or protected-source change is authorized here.
