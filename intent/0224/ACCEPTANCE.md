# Acceptance boundary

Development acceptance requires strict no-content history contracts and actual
Temporal/SQL tests proving no Test Agent call on clarification or supersession,
no resend after uncertain/cancelled dispatch, and reuse of an actual Architect
checkpoint without regenerating it. Replay must not create another model send.

Synthetic output cannot prove useful Brief/Spec/Exam content, semantic duplicate
judgment, live provider costs, independent agent acceptance or the human UI journey.
The real database remains on the held seven-entry baseline; D1 is unsigned/inactive.
No Gate 2, runtime GitHub writing, release, deployment, spending or deletion is
authorized. All I1–I6 live acceptance steps remain open.
