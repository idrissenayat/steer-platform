# Recorded-history composition contract

1. Use the actual production SDK wire verifier, request renderer and operation
   schemas. Do not promote the test-only oracle or duplicate wire-format logic.
2. Bind each scope/development request to its retained original, exact worker
   binding, owner/fencing/reservation and prepared input. Verify every present
   response against its exact request, provider response schema and parsed output.
3. Succeeded steps require matching durable response/result checkpoints. Pending,
   claimed, failed and outcome-unknown states cannot become completed, retryable,
   authorized or novel merely because observations exist. Preserve missing planned
   batches in combined scope coverage. Reject orphaned, duplicate or extra records.
4. The Test Agent receives the exact verified Architect predecessor and original
   source/corrections through the existing renderer, without inherited Exam/chat.
   A clarifying Architect result cannot have a fabricated Test Agent successor.
5. Keep decoding, SDK consistency, source permission, profile approval, semantic
   accuracy, current authority and execution permission distinct. This read-only
   layer does not verify candidate-save execution, sign gates or grant actions.
6. Compose verification within the existing owned content lease. Keep final
   key/records readback and subsequent source closure mandatory; cancellation or
   a caught/late failure cannot leak a successful result or release admission early.
7. Native verification must exercise production composition and independently
   compare with the existing oracle, including corrupt lineage and partial states.
   Keep actual factory integration, target discovery and full C22 acceptance pending
   until their specific evidence exists. No actual provider or profile activation.
