# Development acceptance boundary

- Every source in a complete 34/50-document collection fits and reaches the full
  context unchanged when aggregate bytes fit; source ordering is deterministic.
- Unicode byte limits, missing source groups, access gaps and aggregate overflow
  remain explicit blockers. No partial-context generation or novelty claim.
- The actual editor can choose a Brief outside the old 32-source envelope only
  after recorded assessment and explicit human direction.
- Tampered or absent context digest cannot admit a new assessed operation.
- SQL restore/render retains all 34 sources; old originals keep legacy rendering.
- Repeated preparation and start/worker reconstruction preserve existing exact
  identity, source authority and reservation controls.

Synthetic HTTP/provider responses and disposable SQL are not real human acceptance
or semantic-quality evaluation. All live factories remain uninstalled; D1 and
first-test spending are still unapproved. No real model calls, runtime Git saves,
auth bypass, gates, deployment or release. Old/expired assessment display and
larger-than-bound context handling remain outstanding.
