# Spec

## Distinct internal receipt profile

A Critic runner trust snapshot binds organization, repository, Gate 2, reviewer
provider/task and configuration revision to one HTTPS attestor and Ed25519 key
with exact activation, expiry and optional revocation times. This profile is
distinct from domain-review runner evidence and human identity/approval receipts.

The schema-ordered compact UTF-8 payload binds the same scope plus item, reviewed
artifact revision, exact report path/SHA-256, Builder task, separate review and
Builder execution IDs, review/start/record times, no inherited conversation, no
prior conclusions treated as authority and Builder independence. Every selected
target/identity/run field must match externally supplied expectations. Reviewer
and Builder tasks and their execution IDs must differ.

Verify actual Ed25519 over `steer-critic-runner-attestation/v1` plus NUL and payload
bytes, not a JCS or Ed25519ctx variant. Payload limit is 16 KiB; identifiers are
bounded to 200 characters without controls or surrounding whitespace. Reject
unknown/duplicate fields, alternate serialization, malformed UTF-8, incorrect
canonical base64, wrong key/domain and unsupported native or domain-review
envelopes. No report verdict is carried or generated by this receipt.

Exact UTC nanosecond chronology is activation <= start <= review <= record <=
evaluation. Current key validity is half-open; current revocation rejects. Return
the earlier expiry or scheduled revocation as validBefore, not a freshness lease.

## Current-head native Git composition

A native Critic reference may explicitly select runner trust/proof path+digest,
configuration revision and review/Builder execution IDs. Configuration revision
is not present in retained native Critic records, so it remains an external
governed selection, not a fabricated field inserted into those records.

Require consistent native fresh-context claims before runner reads. Collect both
selected sources from the actual current source head under existing byte, blob,
SHA-256, scope and path checks. Trust/proof encoding must match the helper's
schema-ordered hashes. Bind provider/task/time/digest to the exact native report,
Builder to the existing selected Builder task and scope to the actual collector.
Receipt recording must precede or equal every canonical gate signature.

Startup source paths cannot alias current/history/policy/domain or other selected
trust/proof paths. Once configured, missing, forged, inconsistent or stale runner
evidence cannot fall back to a raw self-declaration. Unsupported or absent runner
configuration does not install a default provider.

Expose immutable nativeCriticRunner (null when not configured) alongside the
unchanged native report and optional finding history. Include every Critic and
domain runner key in common-evaluation and final-completion validity checks.
Preserve 64-KiB receipt sources, 512-KiB native reports, aggregate 8 MiB, the whole-
call fifteen-second budget, current head/actor, single-flight and draining shutdown.

## Non-authority boundaries

The selected key's signature verifies an assertion, not truthful isolation, real
provider ownership, governed configuration/Builder selection, completeness of
history, prior reviewer provenance, resolution evidence or a passing review.
Those remain separately required. Current native reports remain HOLD and the
actual gate policy remains blocked. gateVerified/writeAuthorized stay false.

This is not an actual OpenAI/Codex runner format or provider binding. No trust root,
runtime key, public package API, writer or signature issuer is installed. Existing
commercial provider-recorded human approvals are not changed or converted. All
five R5 findings and signed requirements remain open.
