# Development acceptance

- Both original native records parse unchanged and retain all findings and claims.
- Counters derive from entries; duplicate, omitted and contradictory entries reject.
- Fresh-context counterclaims or same Builder task never become independence.
- Wrong target, source hash, task/provider, invalid/future time and unknown fields reject.
- Unsupported passing/preflight formats cannot become a canonical passing review.
- Native Git collection retains original bytes and the actual policy remains blocked.
- Admission, source limits, final-head movement and post-signature timing fail closed.
- Source/reviewer/history verification requirements and non-authority flags remain.
- Full repository checks pass without changing architectural allowlists or protected sources.

Development acceptance is not Gate 2, reviewer authentication, live GitHub evidence
or release qualification.
