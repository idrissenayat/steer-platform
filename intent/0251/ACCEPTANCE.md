# Engineering acceptance boundary

- Previous/next requests name exact numbered revisions and show exact retained
  bytes, while unsaved current text and the preserved save base remain unchanged.
- Numbered history never enables replacement, including navigation to the newest
  number. A fresh latest read is necessary before explicit editor replacement.
- Unknown writes, conflicts, bad selectors, substituted/regressing responses,
  denied records, closure and late replies cannot silently replace/rebase work.
- Production React component tests check focus, safe rendering and automated axe
  rules. This is not real-browser visual, narrow-screen or human acceptance.
- HTTP/SQL checks prove historical content and newer latest metadata coexist under
  synthetic read-only grants, with key/owner denial and no extra stored revision.

The live records backend remains uninstalled and D1 inactive. No paid provider,
Git runtime save, gate, auth bypass, deployment or deletion is authorized. Older
agent-run and expired/superseded scope-result display remain separate open work.
