# 0328 — Complete draft validation at preparation boundaries

Continue the actual authenticated intent journey without changing the stack,
signed requirements, user drafts or activation/spending authority.

Both scope and drafting preparation reread the same encrypted draft during each
read-only validation phase. Reuse one exact snapshot within that phase, but place
the complete final draft/key/lifecycle comparison after evidence closure. Open a
new phase before admission, before original preservation and before readiness.

Success means exact immutable originals and existing recovery behavior survive,
while late draft changes cannot release readiness or authorize the next effect.
Measure whole actions honestly; fewer key lookups alone do not complete C22.

Non-goals: live model calls, runtime GitHub writes, records-policy adoption,
authentication changes, UI redesign, signatures, release or spending.
