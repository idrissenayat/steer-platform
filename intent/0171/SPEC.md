# Development spec

- Reuse the production Next.js authoring UI, HTTPS gateway, identity runtime,
  actual disposable Keycloak and encrypted PostgreSQL browser session store.
- Use an explicitly scoped native Git policy/selection fixture and actual App JWT
  verification. Historical signer/qualification/observer evidence stays synthetic;
  the current browser human uses the real local provider session.
- Confirm exact content and destination in the guarded opt-in test renderer.
  Policy satisfaction still returns a denied save, false gate/write flags and the
  existing missing governance/provenance/action-time requirements.
- Assert no write-token request, Git HEAD change, Brief or operation marker, exposed
  assessment details, success receipt or enabled second UI submission.
- Reconstruct runtime against the same encrypted store; manually recover status as
  not-found, not committed. Deny current observer loss and Git-committed human
  revocation without granting authority or mutating the authoring destination.
- Isolate the browser context and native Git fixture; restore the existing gateway
  and clean all owned resources. Do not alter live configuration or protected canon.
