# Specification

1. Add private construction proof keyed by the exact review method and scope.
   Genuine forwarding of that method preserves proof; bound/copied/unregistered
   methods use their original full review. Reject method/scope replacement.
   No public package export, tool input, marker or profile flag supplies proof.
2. Share only one complete immutable corpus within one read-only computation.
   Use the existing native corpus session: exact commit/blob/content identity,
   every consumed-source grant, every product/lifecycle selection, current
   all-grants revision and fresh head checks remain. Incomplete evidence stays
   on the full-read path and cannot manufacture clearance or a new intent.
3. Each repeated source review still reads the exact latest draft twice,
   validates both evidence/provenance results and recomputes/verifies its
   output. After the enclosing corpus's final freshness callback, reopen the
   exact draft once more to detect a late edit, hold or lost key.
4. Enclose a standalone final save review and all repeated final/source reviews
   inside one package preview. Preserve all history/original/recorded-scope/
   destination/draft reads and comparisons. Return only after the session and
   final current-authority validation complete.
5. Keep confirmation admission/persistence unchanged. Each preview opens a new
   session, including the second preview after persistence. No source bytes or
   proof may cross an effect, request or owner lifetime. No policy is cached.
6. Deny skipped/replayed/empty/premature/nonvoid windows, swallowed failures,
   overlapping/unawaited reads, changed ports and late callback results. Await
   actual work, not a tracker's substitute value. On closure/failure, withhold
   results while owner admission retains actual pending work until drainage.
7. Verify the private proof and hostile callbacks, actual native body counts,
   late permissions/head/draft/key/hold changes, lifecycle closure and existing
   admission limits. Run native candidate-save checks, the authenticated joined
   journey, broad package/application regression, types and production build.
   Retain all measured provider attempts and exact source/harness hashes.

The fixed checklist stays at 17/25 until a whole checkpoint passes. A single
undelayed run is not the complete 20-warm/3-cold/4-concurrent, two-direction C22
protocol. Preserve the 200-attempt ceiling, prior failed evidence and separate
records/model/runtime/GitHub/UI acceptance requirements.
