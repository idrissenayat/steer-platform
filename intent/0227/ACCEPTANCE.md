# Acceptance boundary

Development acceptance requires the actual HTTP handler-to-encrypted-SQL path to
return coherent, scoped progress and verified captured role results without a
dispatch or save capability. Permission loss, profile mismatch, records holds and
source/step inconsistency must withhold private content. Expiry cannot renew work.
Newer human text must remain intact, and uncertain dispatch must not become retry.

Integration tests use disposable PostgreSQL, actual encryption/SDK serialization
and synthetic identity, records grants and model responses. They do not establish
live provider provenance, document quality, human usability, independent Test Agent
acceptance or end-to-end I1–I6 completion. Generated Exam content remains NOT RUN.

The actual runtime/editor binding, real migrations, records keys and grants remain
inactive. D1 is unsigned/inactive. No paid model usage or runtime Git saving is
authorized. Protected architecture, canonical Exam and accepted policy are unchanged.
