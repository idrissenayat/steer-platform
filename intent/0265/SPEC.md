# 0265 — New-candidate destination resolution

1. Provide a server-only adapter compatible with the existing package-preview
   destination port. Explicit configuration fixes organization/subject/product/
   repository/branch/configuration revision and a bounded item allowlist. Validate
   the complete reader binding before and throughout each operation.
2. Accept the strict existing preview input and structurally verified exact review.
   Deny caller configuration/lifecycle fields, foreign scope, non-null proposal IDs,
   existing-item direction and changed review/draft/choice bindings. No new endpoint,
   client-only success state or startup installation.
3. New-distinct requires the current branch head to equal the reviewed commit and
   the intended item root/descendants to be absent in the verified bounded inventory.
   Wrong identity, invalid topology, truncation, links or corrupt inventory cannot
   become empty/newness claims. Item allocation is outside this adapter.
4. New-linked additionally requires a different allowed item Brief at that same
   reviewed commit, exact path/content digest/blob OID/regular mode and current
   target product/source permission. Reject legacy mapping, stale target revision,
   executable/symlink content and byte substitution. Return only the exact relation.
5. A mandatory trusted current policy service must verify new-item admissibility,
   lifecycle and grants. Its evidence binds complete scope, request/review digests,
   head/tree, item and relationship. Recheck evidence and principal after I/O; reject
   changed, expired, future-dated, overlong or mismatched proofs. A schema/digest,
   configured item or a test assertion never supplies live policy authority.
6. Recheck current head after policy I/O and source access before release. Bound
   four concurrent operations and each operation to 30 seconds; pending dependencies
   retain admission through timeout/closure until actual drain. Preserve generic
   errors without source text or policy internals.
7. Produce reproducible `new-candidate` destination metadata with no prior bundle
   or amendment. Stable authority/source evidence determines its digest; observation
   timestamps are validated independently and cannot continuously change the same
   proposal identity. No consent, operation, write, gate, retry or novelty claim.
8. Keep current save reconstitution, expected-head CAS and independent dispatch
   authority unchanged. This observation does not reserve the absent path or
   enable existing-item mutations. Verify with native temporary Git, synthetic
   provider transport/reviews/authority and existing pure preview planning.

See [process guide](../../docs/NEW-CANDIDATE-DESTINATION.md) and
[evidence](EVIDENCE.md). No formal independent Exam or gate signature is fabricated.
