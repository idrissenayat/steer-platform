# Spec

Provide an explicit opt-in integration command, outside the regular no-Docker unit
suite. Reuse the existing no-network native Git mutation fixture and disposable
PostgreSQL harness. Call the actual Hono/shared preview and save tools, retaining
exact confirmation, request-owned writer lifecycle, operation idempotency, Git
compare-and-swap and verified readback. Create source bytes from submitted draft
facts rather than seeding the saved Brief/marker pair.

Use the production request-bound GitHub writer and store, with a clearly labeled
synthetic identity context and authority callback solely inside the test. These
doubles are not human signatures, verified live membership, provider gate evidence
or a replacement for the always-held production factory. The callback is not
reachable through request JSON, UI or runtime configuration. No actual network
transport, keys, account writes or deployment may occur.

For a successful call, verify exactly the Brief and operation marker were added in
one native Git commit, the stored bytes equal the HTTP preview, and the reported
revision/digest/blob refer to that commit. Recover the receipt through a newly
constructed API/request writer, then feed authenticated status readback into the
real owned PostgreSQL projection runtime and verify actual selected storage.
Duplicate requests must not produce another Git mutation or derived source revision.

Exercise lost acknowledgment followed by status recovery without retry, malformed
confirmation and revoked/absent write authority before mutation, and current grant
denial of status. Keep public errors sanitized, verify writer closure and clean
only test-owned Git data, database rows/events and the disposable PostgreSQL service.
Do not claim the simulated trust boundary is live authority or complete Gate 2.
