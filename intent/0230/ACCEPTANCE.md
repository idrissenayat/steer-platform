# Acceptance boundary

Development acceptance requires the actual production React component graph and
authenticated HTTP transport contracts to complete source review, explicit direction,
clarification, same-run recovery and controlled candidate adoption. Tests must show
that incomplete scope cannot start work and late output cannot replace human edits.
SQL integration must prove current draft/evidence/authority checks with zero writes
from review, plus the existing exact prepare/start/read recorded role pipeline.

Synthetic HTTP/model/source authorities do not establish actual membership,
production source completeness, semantic accuracy, usable live generation,
independent Test Agent acceptance or a saved repository bundle. DOM axe checks do
not replace visual/browser/manual accessibility qualification. I1–I6 remains open.

No signature, D1 records-policy adoption, real migration/configuration/key/grant,
model spending, runtime Git saving, deployment, release or deletion is authorized.
The existing real migration baseline remains held.
