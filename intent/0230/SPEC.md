# Spec — Recorded intent editor journey

## Read-only source metadata

`intent.development.review` is an explicitly granted human query over exact
organization/product/repository, draft ID/revision/digest and scope-input digest.
It cannot accept direction, model profiles, execution configuration, budget or
source bodies from the browser. The owner-bound composition reads the current
encrypted draft and source evidence twice, revalidates identity and mandatory
provenance authority, verifies source bytes and withholds changed or stale output.
It returns server configuration revision and pinned source snapshot for the later
preparation command. No draft, operation, original, reservation or workflow is written.

The query is bounded to four admitted reads and 30 seconds; pending dependencies
retain their slot until settlement. Evidence wire content is limited to 350 KB;
oversized output fails rather than truncating or claiming a complete review.
Incomplete inventory/access/context coverage is visible and blocks preparation.
Declared complete inventory remains distinct from verified production provenance
and semantic duplicate clearance. All authority/save/gate flags remain false.

## Actual editor

Use the existing authenticated conversation, pink/orange design and default-off
draft configuration. A configured draft editor uses recorded development instead
of the older one-shot command; there is no second application or new live switch.
`Preserve and review my intent` first obtains an exact draft acknowledgement, then
queries source metadata only for those unchanged bytes. Lost preservation or newer
typing must not automatically review or develop another snapshot.

The human reviews whole permitted source documents and chooses extend-existing,
new-linked or new-distinct with an explanation. Linked targets must be current
reviewed Briefs. Confirming direction calls prepare, then start only after exact
original preservation is acknowledged. The API remains responsible for current
source/records/model/budget authority. No live authority is inferred from UI flags.

Unknown preparation/start retains the exact request for explicit recovery, with no
automatic replacement. Read-only progress checks use the same operation and stop
after eight minutes or 240 attempts, on errors, hidden/expired sessions or terminal
status. Verified terminal records can resolve an uncertain start without sending
another start; this is outcome recovery, not new dispatch authority.

Clarification results populate the conversation on explicit selection, preserving
all earlier answers verbatim. New answers require preserved/reviewed revision input.
Both role results are previewed before explicitly replacing document fields. Human
edits invalidate source review even if undone; late or superseded results cannot
replace them. Generated originals remain distinct from editable corrections.

HTTPS same-origin requests use no-store, no redirects, bounded UTF-8 bodies and
40-second abort races. No keys, browser storage, provider calls or Git writes are
present in the client. Session/identity changes clear private in-page state.

## Still outside this increment

Owned-draft/operation discovery after refresh, real full-corpus/lifecycle authority,
semantic assessment, authorized records/model installation, cost/eval acceptance,
Git bundle save/reopen and real-browser human acceptance remain open. Canonical
Exam and all signed documents remain unchanged.
