# Acceptance boundary

Development acceptance requires scope controls inside the actual editor's React
graph, fixed authenticated tool requests, exact-request recovery, verified citations,
honest coverage/progress, and no automatic generation/save or replacement of edits.
Transport cancellation, identity/expiry cleanup and portable imports are tested.

JSDOM interactions and structural axe checks are not browser visual acceptance,
color-contrast validation or a signed-in journey against real retained records.
No live model, records, Git writer or gate is activated. The existing legacy
generation gate remains unchanged even when larger-corpus scope batches complete.

Scope-specific discovery after refresh, server-side assessment-to-direction/drafting
consumption, direct opening of proposed Brief paths, larger-context coverage,
expired observation access, semantic quality and real I1–I6 acceptance remain open.
