# Engineering acceptance boundary

- Repeatable corpus/profile/source/expectation digests and no oracle leakage into
  production scope requests.
- All synthetic reference cases pass candidate checks after actual SDK exchange
  verification, with zero network requests and no semantic-acceptance claim.
- Wrong labels with valid citations, truncated qualifiers, absent cases/batches,
  stale references, corrupt/refused exchanges and false authority are detected.
- Complete empty, unknown empty, access gaps and missing whole targets stay
  distinct. Missing data cannot become a passing novelty claim.
- Reports and CLI errors do not expose raw request/output text or secrets.
- Types/build/regressions and documentation links pass; protected hashes remain.

This packet does not sign a gate or complete I1, I3 or I6. The reference labels
need independent adjudication; explanation quality and live provider provenance
are not established. D1 and spending remain inactive and no runtime save occurs.
