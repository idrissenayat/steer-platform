# Development acceptance boundary

- Exact complete assessment reaches the human's recorded direction, Architect and
  fresh Test Agent; earlier Exam and private Architect commentary are excluded.
- Missing, forged, wrong-owner, stale, incomplete or denied assessment cannot
  become preparation/start/context release. Human revisions remain untouched.
- A verified complete empty corpus avoids unnecessary assessment calls. Failed or
  incomplete inventory is blocked, never described as empty or new.
- Repeated preparation preserves one immutable input and adds no model reservation.
- Actual React conversation proceeds assessment → direction → clarification →
  re-assessment → candidates, including same-request lost-response recovery.
- Larger scope batches do not bypass the smaller legacy generation coverage gate.

This is source development with synthetic authority/provider responses and isolated
database tests, not real-browser visual acceptance or live signed-in save/reopen.
D1 remains unsigned/inactive and first-test model spending unapproved. A current
reader is mandatory for assessed-original restoration; historical expired-scope
display remains separate. No automatic semantic clearance, merge, save or gate.
