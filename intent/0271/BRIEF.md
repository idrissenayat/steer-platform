# Intent 0271 — Managed authenticated journey runtime

The recorded intent services exist, but the identity composition root cannot yet
own a complete scoped journey bundle. Newer browser-only intent services also
need resource drainage before identity/storage pools close. Add that explicit
integration boundary without bypassing authentication or activating unsigned policy.

Deliver a governed optional runtime binding, pinned service inventory, current
bundle-use checks, drain-safe ownership, focused authenticated/SQL verification and
updated implementation documentation. No UI/design, credential, real runtime profile,
signed artifact, records migration, model/Git write authority or gate changes.

See [specification](SPEC.md), [runtime guide](../../docs/AUTHENTICATED-INTENT-RUNTIME.md)
and [evidence](EVIDENCE.md). This is development integration, not live I1–I6 acceptance.
