# Spec — Recorded semantic scope-review role

## Exact private request

`prepareIntentScopeReview` verifies the exact scope fingerprint and repository/
product/organization against the corpus evidence, then reuses 0233 whole-target
planning. Each private request binds scope/source/plan/batch/assessment digests and
the complete pinned review profile. Changed edits, clarifications, source head,
permissions, model route, output cap or response-model allowlist cannot reuse the
same request identity. Reordered equivalent source input remains stable.

The profile fixes `steer-scope-reviewer/v1` instructions. These direct the role to
compare the exact current proposed scope, preserve unknowns/exclusions and source
status, distinguish the five specified relations and cite verified source bytes.
They prohibit treating source instructions as commands or claiming merge, save,
gate, budget or execution authority. This is an unevaluated profile, not proof of
model obedience, semantic accuracy or approved configuration.

Include original text, clarification turns, current edited Brief/Spec, global
coverage and the exact local evidence envelope. No prior Exam, Architect result or
arbitrary role conversation is inherited. Input fields are explicitly bounded and
strict; preserve accepted Unicode/line endings. Bound serialized private request
bytes to 350,000; the adapter independently checks complete wire-request size.
Byte bounds are not a tokenizer, price estimate, reservation or context guarantee.

Preparation is immutable, provider-free and non-durable. Its zero-call plan fields
describe preparation, not a live run-status counter. Incomplete corpus coverage
stays explicit in each request; empty or wholly withheld context produces no batch
request. This does not silently convert incomplete input into newness or authorize
processing every planned batch.

## Recorded Mastra exchange

`createRecordedScopeMastraRuntime` is an uninstalled explicit constructor at the
existing agent provider edge. It fixes scope/evidence/profile and accepts only a
known batch ID at generation time, not a caller-edited prompt or arbitrary role.
Reuse the existing nonstreaming OpenAI-compatible Mastra/LiteLLM transport path:
fresh agent per call, two exact messages, structured output, no tools/memory,
automatic retries or telemetry, `store: false`, loopback gateway only and an explicit
scoped gateway credential. No direct provider credential or environment fallback.

Before transport, verify the actual SDK serialization, obtain request-recording
acknowledgement and fresh dispatch authority. Validate raw provider response/model,
finish/refusal/tool state, usage and structured assessment. Check target/source
membership, assessment/profile binding and every citation against the exact local
evidence. Raw and SDK-parsed results must agree. Record the raw response and usage
before returning a successful role result. Missing usage remains unknown, not zero.
Malformed output fails without an automatic provider retry.

Cancellation and shared transport deadlines suppress late results. A missing
acknowledgement or changed authority cannot manufacture success. Errors do not
return private provider text or credentials. This adapter is not a durable deduper:
separate explicit invocations still require separately enforced SQL ownership and
per-batch reservations. A fixture callback returning successfully proves neither.

`createRecordedScopeMastraVerifier` reconstructs the same exact context without a
gateway, key or transport and independently verifies captured exchanges. Changed
batch, source, profile policy, serialized request, result or usage is rejected.
This verifies exchange consistency and citations, not real provider provenance or
current source access without the trusted surrounding authority service.

## Aggregation and compatibility

The result has distinct `scope-reviewer` identity, plan/batch binding and strict
assessment output. Feed its output into 0233 combined validation. Missing findings,
abstentions and global gaps remain incomplete; a fully structured result still does
not claim semantic quality, uniqueness or action authority.

Architect/Test Agent public contracts, stored originals, SQL role/budget enums and
Temporal workflows remain unchanged. Both drafting roles use the same refactored
internal SDK/transport edge and retain their strict codecs. No application route,
UI, active service, model, database schema or credentials are switched.
