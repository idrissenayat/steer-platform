# Bounded immutable corpus-read feasibility

0298 established that the existing per-file read protocol exceeds the complete
request budget even if historical records validation becomes free. Before another
production optimization, test whether the representative corpus can be collected
in bounded dependency waves through the current code-host seam.

This increment implements only the corpus portion of that experiment. It must
not be mistaken for an installed adapter, an integrated authorization budget,
records/read-graph feasibility or a completed interactive workflow. The user's
priority remains the [actual intent journey](../../docs/INTENT-JOURNEY-PLAN.md).

Use disposable native Git objects and explicitly injected synthetic transport.
Preserve individual source grants, selection, exact commit membership, pointer
and manifest lineage, document bytes and deny-on-change behavior. Do not call a
model, use credentials, write through the live runtime, change gates or raise
the [existing performance limits](../../docs/INTENT-CAPTURE-PERFORMANCE.md).

Outcome: [specification](SPEC.md), [observed evidence](EVIDENCE.md) and
[machine-readable result](FEASIBILITY.json). The next experiment must cover real
records/history composition and its outer authorization cost before production
integration; another standalone corpus improvement is not the next milestone.
