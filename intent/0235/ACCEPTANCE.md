# Acceptance boundary

Development evidence must show one immutable review after concurrent admission,
one reservation per batch under concurrent claims/takeover, one newly acknowledged
dispatch, and no dispatch from ambiguous/replayed results. Scope/drafting contention
must honor one cap. Wrong roles, tenants, products, inputs and expired or revoked
authority must fail closed; SQL must reject resets and invented success.

Real SQL and migrations may run only inside the harness's disposable fixture
database. Synthetic authority and budget rows do not grant actual access, approved
records retention, model spending or Git saving. This layer is not a completed
scope-review runner, semantic accuracy evaluation, signed Exam or human acceptance.
