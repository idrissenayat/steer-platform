# 0266 implementation specification

1. Expose explicit, uninstalled existing-item and composed destination factories
   compatible with the real package-preview port. No new tool, endpoint, frontend,
   model call, SQL schema, credentials, execution or write authority.
2. Bind current human/product/configuration, reviewed current Git head and exact
   `items/<id>/BRIEF.md`. Validate full bounded inventory, regular tree/file modes,
   exact bytes, native blob IDs and reviewed digest. Legacy and foreign targets deny.
3. Require independently verified current governed lifecycle policy binding the
   request, review, head, repository/item trees and Brief metadata. File presence
   is never evidence that an item was not pulled. Reject invalid scope/time/lifecycle.
4. Pre-pull candidates require verified CANDIDATE pointer, manifest, all three
   documents and root Brief mirror. Retain exact prior manifest digest and only
   the prior relationship confirmed by current policy and configured scope.
5. Proposal-only targets produce a first amendment with deterministic domain-bound
   UUIDv8 identity and absent proposal path. Keep the original current target and
   null parent digests. Canonical Brief/Spec/Exam and gates are not write targets.
6. Reject every selected existing proposal before I/O until its immutable target
   can be bound independently of the current final-review snapshot. Record why
   proposal commit B cannot equal its original target A; never fabricate a native
   Git success fixture by pretending those two commits are the same.
7. Recheck current source/human permissions, branch and stable policy after I/O.
   Enforce proof validity through release and bounded work even after cancellation.
8. The shared router uses only the human action. No error path changes direction
   or falls back to new work. Each branch retains its four-slot/30-second bound.
9. Native-Git/pure-preview tests verify positive candidate and first-amendment
   paths, fidelity, corruption, stale sources, lifecycle/grant changes, cancellation,
   selected-parent incompatibility and no canonical mutation. Keep synthetic
   provenance, live acceptance and actual governed service implementation distinct.
