# Acceptance boundary

Developer tests only. SQL operations, reservations, encrypted original/result
stores and request preparation are actual disposable components. Identities, grants,
keys, budget figures, model outputs and the observation map are synthetic. Runtime
reconstruction in one test process is not provider-record durability, machine-crash
recovery, backup restoration or an independent Test Agent acceptance verdict.

The runner is not registered as a Temporal activity, API route or real model
binding. D1 remains unsigned/inactive; all I1–I6 acceptance stays open. The real
database migration hold, live model-budget hold and GitHub-save permissions remain
unchanged. No gate, spending, deployment, release, deletion or signed-source change.
