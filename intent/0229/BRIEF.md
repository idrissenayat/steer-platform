# Brief

The start API needs a preserved, exact development input; an editor's text or a
workflow reference alone is insufficient. Preparation must preserve the actual
source and corrections, bind the person's reviewed direction, and recover lost
storage acknowledgements without creating another operation or changing the budget.

This increment assembles that input from existing encrypted draft revisions and
mandatory current evidence/authority services. It stores one immutable original
under the existing SQL operation uniqueness rule. A prepared receipt means the
original was read back exactly, not that generation is authorized or completed.

Source evidence completeness is not inferred from filenames, a lexical candidate
list or successful JSON validation. Full-corpus/lifecycle verification, semantic
assessment, actual editor integration and live activation remain separate work.
