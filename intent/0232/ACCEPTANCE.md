# Acceptance boundary

Development checks must discover legacy/new item roots at one native Git revision;
preserve canonical/candidate/amendment distinctions; omit restricted content/IDs;
retain incomplete coverage for unknown roots, missing sources and limits; and
suppress changed access, lifecycle or head output. The current review HTTP path
must consume these tree/blob reads without generation or Git mutations.

Synthetic GitHub transport and authority/draft fixtures do not prove live provider
access, qualified lifecycle selection, records-policy adoption, semantic accuracy,
large-corpus recall or human UI/save acceptance. No signed source, canonical Exam,
grant, spending or activation is authorized by this increment.
