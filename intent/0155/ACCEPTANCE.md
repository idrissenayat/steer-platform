# Development acceptance

- No default path, implicit confirmation, write callback or generated operation ID.
- Local acceptance binds exact content/target/session and clears on change/expiry.
- Manual status checks validate identity, scope, operation and strict output shape.
- All five outcomes have distinct language; no absent/unknown result triggers retry.
- Prior receipts cannot mark the current draft saved or sign a gate.
- Errors, edit/refresh races, hidden pages and closure suppress stale output.
- Real browser controls work with keyboard, narrow layout and automated WCAG checks.
- Real writer-less runtime stays unavailable; browser-only receipt fixtures are
  explicitly distinguished from provider persistence evidence.
- Full checks pass; documentation and candidate push identify remaining boundaries.
